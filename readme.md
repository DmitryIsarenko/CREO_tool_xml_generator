# CREO Tool XML Generator

Локальный Python-генератор XML с параметрами металлорежущего инструмента
для CREO Parametric. Он читает подготовленные JSON-каталоги геометрии
и режимов резания, рассчитывает параметры и создаёт XML для каждого
типоразмера.

Таблицы из каталогов производителей нужно переносить в JSON вручную.
Проект не извлекает данные из PDF автоматически.

Целевая система — CREO Parametric 8 и выше. Совместимость с отдельными
версиями CREO в рамках текущих проверок не подтверждена.

## Требования

- Windows: существующий метод записи XML использует Windows-пути.
- Python 3.12 или новее: нужен для синтаксиса существующих f-строк.
  Пример проверен на Python 3.12.10.
- Сторонние Python-пакеты не нужны. Файл `requirements.txt` пуст.
- CREO не нужен для генерации примера. Для проверки импорта XML нужен
  CREO и модели сборок, на которые ссылается XML.

## Быстрый старт: безопасный пример

Откройте терминал в корне скачанного репозитория. В Git Bash для текущей
рабочей копии это каталог `d:/PROJ/CREO_tool_xml_generator`:

```bash
cd /d/PROJ/CREO_tool_xml_generator
python --version
python -m src.tool_updater.demo
```

Если проект находится в другом месте, откройте терминал в его корне.
Менять пути в исходном коде для demo не требуется.

Demo создаёт одну сферическую фрезу диаметром 6 мм с двумя зубьями.
Входные данные искусственные, не из каталога производителя.
**Не используйте результат для обработки на станке.**

Результат в текущей рабочей копии:

```text
d:/PROJ/CREO_tool_xml_generator/generated_xmls/demo/
    demo_ball_D6.0_L12-L60_NOT_FOR_MACHINING.xml
```

Журнал дополняется в
`d:/PROJ/CREO_tool_xml_generator/src/logs/log.log`.
При переносе проекта оба пути вычисляются относительно корня проекта.
XML и журнал исключены из Git.

Demo пишет результат во временную подпапку, проверяет наличие одного
XML и разбирает его XML-парсером. Затем переносит файл в итоговую папку.
Повторный запуск заменяет одноимённый demo-файл, но не удаляет остальные.
Производственные пути вывода из конфигурации не используются.
Расчёты используют существующий класс `BallMill` и общие настройки.

Подробности примера:
`d:/PROJ/CREO_tool_xml_generator/examples/demo/README.md`.

## Пример JSON → XML

Геометрия из
`d:/PROJ/CREO_tool_xml_generator/examples/demo/geometry.json`:

```json
{
  "6.00": {
    "flute_diam": 6,
    "flute_len": 12,
    "full_body_len": 60,
    "full_body_diam": 6,
    "order_no": "DEMO ONLY - synthetic tool, not for machining"
  }
}
```

Режимы заданы отдельно в
`d:/PROJ/CREO_tool_xml_generator/examples/demo/cut_data.json`.
Файл содержит шесть групп ISO. Например, для `iso_N` заданы скорость
резания `Vc = 150` и подача `F = 400` для группы диаметра `6.00`.
Это входные значения: итоговые режимы зависят от коэффициентов класса
инструмента и общих настроек. Число зубьев передаёт точка входа demo.

Фрагмент созданного XML, не самостоятельный документ:

```xml
<MfgParam Name="CUTTER_DIAM" Value="6.00"/>
<MfgParam Name="NUM_OF_TEETH" Value="2"/>
<MfgParam Name="FLUTE_LENGTH" Value="12"/>
<MfgParam Name="TOOL_COMMENT" Value="DEMO ONLY - synthetic tool, not for machining"/>
```

## Работа со своими каталогами

Это отдельный ручной сценарий. Его нельзя запускать с исходными путями
из конфигурации: они привязаны к машине автора.

1. Выберите отдельную выходную папку, не рабочую библиотеку инструмента.
   Существующие одноимённые XML могут быть перезаписаны.
   Ветка Git не защищает внешние файлы от перезаписи.
2. В `d:/PROJ/CREO_tool_xml_generator/src/tool_updater/config.py` задайте:
   - `abs_path_to_dir_where_project_is_located` — абсолютный путь к корню
     вашей копии проекта;
   - `abs_path_to_dir_where_to_create_tool_xmls` — абсолютный путь
     к отдельной выходной папке.
   Не добавляйте завершающий слэш.
3. Подготовьте два корректных JSON: геометрию и режимы резания.
   Используйте структуру данных выбранного класса инструмента.
   Универсальной схемы для всех классов нет.
4. Разместите данные в подходящей подпапке каталога
   `d:/PROJ/CREO_tool_xml_generator/src/tool_updater/catalogs/`.
   Существующие подпапки разделены по типу, производителю и серии.
   Среди файлов есть черновики и шаблоны, не все из них — корректный JSON.
5. В нужной функции `gen_*` файла
   `d:/PROJ/CREO_tool_xml_generator/src/tool_updater/main.py` настройте
   вызов `ToolGenerator.create_tools()`: класс инструмента, оба входных
   пути, выходной путь, число зубьев, префикс и суффикс имени.
   Для XML используйте `debug_mode=0`.
6. В `main()` оставьте только нужные вызовы функций генерации.
   Сейчас активен `gen_ballmills()`: он обрабатывает две серии Gesac,
   а не demo-данные. В одной функции может быть несколько вызовов
   генератора — проверьте каждый.
7. Для некоторых сборных инструментов пути к каталогам оправок заданы
   прямо в классах. Двух настроек из `config.py` для них недостаточно.
   Проверьте используемый класс до запуска.
8. После проверки всех путей запустите из корня проекта:

   ```bash
   python -m src.tool_updater.main
   ```

9. Проверьте файлы и журнал. Затем проверьте импорт в CREO, геометрию,
   сборки, единицы измерения и режимы резания. Проверку должен выполнять
   специалист до применения результата на станке.

Производственный запуск со всеми сериями в текущей проверке не выполнялся.
В отличие от demo, он не проверяет созданные XML автоматически.
Метод записи может скрыть ошибку: отсутствие исключения не подтверждает
создание файла.

## Представленные типы инструмента

| Группа | Классы и сценарии в коде |
| --- | --- |
| Осевой инструмент | Свёрла, центровки, зенковки, цековки, развёртки, метчики |
| Фрезерный инструмент | Концевые, сферические, тороидальные, фасочные, резьбовые, дисковые, грибковые, сборные фрезы и фрезы внутреннего радиуса |
| Токарно-фрезерные сборки | Варианты оправок и адаптация длин инструмента |
| Режимы | Группы материалов, черновая и чистовая обработка |

Наличие класса не означает, что все каталоги, комбинации оправок
и результаты проверены в CREO.

## Ограничения и статус проверки

- Проверенный demo-сценарий создаёт XML с искусственными данными.
  Разбор XML-парсером подтверждает синтаксис, но не совместимость с CREO
  и не правильность технологических расчётов.
- XML содержит ссылки на модели сборок. Необходимые модели CREO
  не поставляются с demo-примером.
- Автоматической проверки схемы всех входных каталогов нет.
- Полноценного CLI с выбором серии и путей нет: рабочий сценарий
  настраивается изменением конфигурации и вызовов в коде.
- Технологические параметры и ограничения оправок требуют отдельной
  проверки специалистом.
- Выбор лицензии и права на публикацию данных производителей
  пока не подтверждены. Наличие данных в репозитории не подтверждает
  право на их повторную публикацию.
